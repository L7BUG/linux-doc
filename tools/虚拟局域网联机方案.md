# 虚拟局域网联机方案：用云服务器实现异地局域网游戏

## 1. 背景

你和朋友相隔两地，但想玩只支持局域网（LAN）联机的游戏。如果有一台带公网 IP 的云服务器闲置，就可以用它作为中转，把双方的电脑"拉"到同一个虚拟局域网中，让游戏以为你们在同一张物理交换机下。

本文涵盖 5 种方案的原理、完整配置和适用场景。

---

## 2. 方案全景对比

```
                        难度    延迟    需要服务器    L2 广播    推荐场景
WireGuard               中      最低     需要          ✗          大多数游戏
Tailscale               极低    低       不需要        ✗          不想折腾的首选
ZeroTier                极低    低       不需要        ✓          需要广播的老游戏
n2n (supernode)         中高    低       需要          ✓          自建广播网络
OpenVPN (tap 模式)      高      中       需要          ✓          兼容性要求最高的场景
```

---

## 3. 前置知识：L2 vs L3 虚拟网络

在动手前，理解这一点可以避免很多困惑：

```
L3（IP 层）虚拟网络：
  你的游戏告诉 OS："连接 192.168.99.3:27015"
  OS 查路由表 → 走 wg0 接口 → 发到对端
  ✓ 绝大多数游戏（Minecraft、CS、泰拉瑞亚、饥荒等）

L2（链路层）虚拟网络：
  你的游戏发广播包："谁是 192.168.0.x 的游戏主机？请回答！"
  只有 L2 网络能转发广播包
  ✗ WireGuard / Tailscale 不支持
  ✓ ZeroTier（须开启桥接）、n2n、OpenVPN tap 模式支持
```

> **简单判断**：如果你能在游戏里手动输入 IP 地址加入房间，WireGuard 就够了。如果游戏只有「扫描局域网」按钮，你需要 L2 方案。

---

## 4. 方案一：WireGuard（推荐首选）

WireGuard 是 Linux 内核主线支持的 VPN 协议，延迟最低，配置简洁。三台机器组成星型网络：云服务器为中心节点，你和朋友各为边缘节点。

### 4.1 网络拓扑

```
你 (192.168.99.2)  ←──→  云服务器 (192.168.99.1)  ←──→  朋友 (192.168.99.3)
                              ↑
                        公网 IP，负责转发流量
```

### 4.2 安装

```bash
# Arch Linux
sudo pacman -S wireguard-tools

# Debian / Ubuntu
sudo apt install wireguard

# Windows
# 从 https://www.wireguard.com/install/ 下载安装包
```

### 4.3 云服务器配置

```bash
# 生成密钥对
cd /etc/wireguard
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key

# 查看密钥（后续配置需要）
cat server_private.key
cat server_public.key
```

`/etc/wireguard/wg0.conf`：

```ini
[Interface]
Address = 192.168.99.1/24
ListenPort = 51820
PrivateKey = <服务器私钥>

# 允许客户端之间互相通信
PostUp = sysctl -w net.ipv4.ip_forward=1
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT
PostUp = iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT
PostDown = iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# 你的电脑
[Peer]
PublicKey = <你的公钥>
AllowedIPs = 192.168.99.2/32

# 朋友的电脑
[Peer]
PublicKey = <朋友的公钥>
AllowedIPs = 192.168.99.3/32
```

### 4.4 客户端配置

你和朋友各自生成密钥后，编写 `/etc/wireguard/wg0.conf`：

```ini
[Interface]
Address = 192.168.99.2/24          # 朋友换成 192.168.99.3/24
PrivateKey = <你刚生成的私钥>

[Peer]
PublicKey = <服务器的公钥>
Endpoint = <云服务器公网IP>:51820
AllowedIPs = 192.168.99.0/24      # 只路由虚拟内网流量
PersistentKeepalive = 25           # 维持 NAT 映射，防止运营商断流
```

### 4.5 启动与验证

```bash
# 三台机器都执行
sudo wg-quick up wg0

# 设为开机自启
sudo systemctl enable wg-quick@wg0

# 验证连通性（从你的电脑）
ping 192.168.99.1    # ping 服务器
ping 192.168.99.3    # ping 朋友

# 查看连接状态
sudo wg show
```

### 4.6 云服务器防火墙放行

```bash
# 如果开启了防火墙，需要放行 WireGuard 端口
sudo ufw allow 51820/udp

# 或 firewalld
sudo firewall-cmd --add-port=51820/udp --permanent
sudo firewall-cmd --reload
```

### 4.7 游戏怎么连

- **作主机的人**：在游戏里创建房间，记下自己的 WireGuard IP（如 `192.168.99.2`）
- **作客机的人**：在游戏里选「直接连接」，输入 `192.168.99.2`

## 5. 方案二：Tailscale（最省心）

如果你不想折腾密钥、iptables、防火墙，Tailscale 几乎零配置。它是 WireGuard 的上层封装，免费额度足够个人使用（3 个用户，100 台设备）。

### 5.1 安装

```bash
# Arch Linux
sudo pacman -S tailscale

# 或官方脚本（所有 Linux 发行版通用）
curl -fsSL https://tailscale.com/install.sh | sh

# Windows / macOS
# 从 https://tailscale.com/download 下载安装包
```

### 5.2 启动与加入网络

```bash
# 三台机器都执行
sudo systemctl enable --now tailscaled

# 登录并加入你的 Tailscale 网络
sudo tailscale up

# 浏览器会弹出登录页面，用 GitHub / Google / Microsoft 账号登录
```

完成后，每台机器会自动获得一个 `100.x.x.x` 的 Tailscale IP。运行 `tailscale status` 查看：

```
$ tailscale status
100.64.0.1    your-server    linux    -
100.99.0.2    your-pc        linux    -
100.77.0.3    friend-pc      windows  -
```

游戏里直接用这些 IP 即可。

### 5.3 Tailscale 不需要云服务器

Tailscale 的协调服务器由 Tailscale 官方托管，你的云服务器只是在网络中的普通节点。所以：

- **如果只是云服务器闲置**：可以不装 Tailscale，直接用 WireGuard 方案
- **想用云服务器做 DERP 中继**：在服务器上运行 `tailscale up --advertise-exit-node`，可以在双方无法直连时（NAT 严格）作为中继

## 6. 方案三：ZeroTier（自带 L2 广播）

ZeroTier 和 Tailscale 类似，但多了一个关键能力：**原生支持 L2 以太网桥接**。如果游戏需要广播发现（老游戏、部分独立游戏），ZeroTier 是零配置首选。

### 6.1 安装

```bash
# Arch Linux
sudo pacman -S zerotier-one

# Debian / Ubuntu
curl -s https://install.zerotier.com | sudo bash

# Windows / macOS
# 从 https://www.zerotier.com/download/ 下载
```

### 6.2 创建网络

1. 去 https://my.zerotier.com 注册账号
2. 点击 "Create A Network"，得到一个 Network ID（如 `8056c2e21c000001`）
3. 在设置里选一个私有 IP 段（默认 `10.147.x.x` 就可以）

### 6.3 加入网络

```bash
# 三台机器都执行
sudo systemctl enable --now zerotier-one
sudo zerotier-cli join <你的 Network ID>
```

回到网页后台，在 Members 列表里勾选这三台设备（允许加入）。等几秒后确认：

```bash
$ sudo zerotier-cli listnetworks
200 listnetworks <nwid> <name> <mac> <status> <type> <dev> <ZT assigned ips>
200 listnetworks 8056c2e21c000001 my-lan 02:xx:xx:xx:xx:xx OK PRIVATE zt0 10.147.17.5/24
```

### 6.4 开启以太网桥接（L2 广播）

在 my.zerotier.com 上，进入网络设置，勾选 **Allow Ethernet Bridging**。

或通过 API 开启：

```bash
curl -X POST "https://my.zerotier.com/api/v1/network/<Network ID>" \
  -H "Authorization: bearer <API Token>" \
  -H "Content-Type: application/json" \
  -d '{"config": {"allowEthernetOverIP": true}}'
```

### 6.5 搭建 Moon（自定义根服务器，可选）

ZeroTier 默认用官方的根服务器做协调，延迟可能偏高。如果你有云服务器，可以自建 Moon 来降低延迟：

```bash
# 在云服务器上
cd /var/lib/zerotier-one
sudo zerotier-idtool initmoon identity.public >> moons.d/000000xxxxxx.moon
sudo zerotier-idtool genmoon moons.d/000000xxxxxx.moon

# 重启服务
sudo systemctl restart zerotier-one
```

然后在每台客户端上加入这个 Moon：

```bash
sudo zerotier-cli orbit <Moon ID> <Moon ID>
```

## 7. 方案四：n2n（自建 L2 广播网络）

n2n 是一个 P2P L2 VPN 方案，由 supernode（超级节点）和 edge（边缘节点）两层组成。云服务器跑 supernode，双方各跑 edge。

### 7.1 架构

```
你的电脑（edge）──┐
                   ├──→ 云服务器（supernode）──→ 协调打洞
朋友的电脑（edge）─┘
                        ↓
              打洞成功后，流量直接 P2P，不经过服务器
```

### 7.2 安装

```bash
# Arch Linux
sudo pacman -S n2n

# Debian / Ubuntu（可能需要从源码编译）
sudo apt install build-essential cmake libcap-dev
git clone https://github.com/ntop/n2n.git
cd n2n && ./autogen.sh && ./configure && make && sudo make install
```

### 7.3 云服务器：启动 supernode

```bash
# 基本启动（端口 7654）
sudo supernode -p 7654 -f

# 设为 systemd 服务
```

创建 `/etc/systemd/system/supernode.service`：

```ini
[Unit]
Description=n2n supernode
After=network.target

[Service]
ExecStart=/usr/bin/supernode -p 7654 -f
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now supernode
```

**放行防火墙**：`sudo ufw allow 7654/udp`

### 7.4 客户端：启动 edge

```bash
# 你的电脑
sudo edge -d tun0 -a 192.168.100.2 -c mygame -k mypassword \
  -l <云服务器公网IP>:7654 -f

# 朋友的电脑
sudo edge -d tun0 -a 192.168.100.3 -c mygame -k mypassword \
  -l <云服务器公网IP>:7654 -f

# 参数说明：
#   -d  虚拟网卡名称（tun0）
#   -a  分配的虚拟 IP
#   -c  社区名称（同一个社区才能互连）
#   -k  加密密钥（同一个密钥才能互连）
#   -l  supernode 地址
#   -f  前台运行（调试用，后台运行去掉此参数）
```

### 7.5 n2n 的优势

- **L2 广播**：游戏扫描局域网能直接发现对方
- **P2P 直连**：打洞成功后流量不经过云服务器，延迟最低
- **不依赖第三方服务**：所有组件都在你自己的服务器上

## 8. 方案五：OpenVPN tap 模式（兼容性最强）

当其他方案都不行时（极老游戏、特殊网络环境），OpenVPN 的 tap 模式基于以太网帧转发，兼容性天花板。

### 8.1 原理

```
OpenVPN tun 模式（L3）→ 路由 IP 包，不传广播
OpenVPN tap 模式（L2）→ 桥接以太网帧，传广播
```

### 8.2 云服务器配置

```bash
sudo pacman -S openvpn easy-rsa

# 初始化 PKI
cd /etc/easy-rsa
sudo ./easyrsa init-pki
sudo ./easyrsa build-ca
sudo ./easyrsa build-server-full server nopass
sudo ./easyrsa build-client-full client1 nopass
sudo ./easyrsa build-client-full client2 nopass
sudo ./easyrsa gen-dh
```

`/etc/openvpn/server.conf`：

```
port 1194
proto udp
dev tap                          # ← tap 不是 tun
ca /etc/easy-rsa/pki/ca.crt
cert /etc/easy-rsa/pki/issued/server.crt
key /etc/easy-rsa/pki/private/server.key
dh /etc/easy-rsa/pki/dh.pem
server-bridge 192.168.100.1 255.255.255.0 192.168.100.100 192.168.100.110
client-to-client                 # 允许客户端互通
keepalive 10 120
cipher AES-256-GCM
verb 3
```

> **注意**：`server-bridge` 需要额外配置网桥（`brctl`），比 WireGuard 繁琐得多。除非确有必要，不推荐优先使用。

## 9. 延迟优化

虚拟局域网联机最大的痛点是延迟。几个实用优化方向：

### 9.1 选择离双方都近的云服务器

```bash
# 测试延迟
ping <云服务器 IP>
# 找出你和朋友到服务器的 ping 值，取较大的那个作为实际游戏延迟

# 理想情况：
#   你 → 服务器：15ms
#   朋友 → 服务器：20ms
#   实际游戏延迟：≈ 20ms（服务器转发开销 < 1ms）
```

国内云服务器选择建议：

| 你 | 朋友 | 推荐服务器位置 |
|----|------|--------------|
| 北京 | 上海 | 济南 / 郑州 |
| 广东 | 四川 | 长沙 / 武汉 |
| 东北 | 华南 | 上海 / 杭州 |

### 9.2 检查是否走了中继

```bash
# Tailscale
tailscale status
# 看是否有 "relay" 标记——如果是 "relay"，说明在走中继，延迟会高

# ZeroTier
sudo zerotier-cli listpeers
# 看 path 字段：直连显示公网 IP，中继显示 "RELAY"
```

WireGuard 默认就是直连的，只要服务器开启了 IP 转发，双方流量会通过服务器中转（稳定可控）。

### 9.3 开启 BBR 拥塞控制

```bash
# 检查是否已启用
sysctl net.ipv4.tcp_congestion_control

# 启用 BBR
echo "net.core.default_qdisc=fq" | sudo tee -a /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

### 9.4 MTU 调整

隧道封装会增加包头，可能导致 MTU 超标引发丢包：

```bash
# WireGuard 客户端 [Interface] 段
MTU = 1420

# ZeroTier
sudo zerotier-cli set <Network ID> mtu 1400
```

## 10. 故障排查

### 你能 ping 服务器，但 ping 不通朋友

```bash
# 检查服务器端 IP 转发
sysctl net.ipv4.ip_forward          # 应该是 1

# 检查 iptables FORWARD 规则
sudo iptables -L FORWARD -v         # 应有 wg0 ACCEPT 规则

# 检查服务器 Peer 配置中 AllowedIPs 是否包含双方的虚拟 IP
```

### 游戏能连上但秒断

通常是 MTU 问题（见 9.4 节），降低 MTU 到 1400-1420 范围重试。

### ZeroTier / Tailscale 能连上但游戏扫不到房间

- 确认游戏用的是**局域网扫描**还是**直接 IP 连接**
- 如果必须扫描：开启 ZeroTier 以太网桥接（见 6.4 节），或改用 n2n

### NAT 严格导致无法直连

```
你的 NAT ──→ 服务器 ←── 朋友的 NAT
   (锥形 NAT)            (对称 NAT)
                         ↑
                   对称 NAT 很难打洞，流量可能需经服务器转发
```

- **WireGuard**：服务器开启了转发 (`ip_forward=1`)，流量通过服务器中转，不受 NAT 类型影响
- **Tailscale**：使用 DERP 中继（在云服务器上运行 `tailscale up --advertise-exit-node`）
- **ZeroTier**：流量自动走 Moon 或官方根服务器中继

### 防火墙放行游戏端口

主机方的防火墙不仅要在物理网卡上放行游戏端口，虚拟网卡也同样需要：

```bash
# 例如 Minecraft 服务器（端口 25565）
# 确保 iptables 也可以接受来自 wg0 的流量
sudo iptables -A INPUT -i wg0 -p tcp --dport 25565 -j ACCEPT
sudo iptables -A INPUT -i wg0 -p udp --dport 25565 -j ACCEPT

# 或者简单粗暴地信任整个 wg0 接口
sudo iptables -A INPUT -i wg0 -j ACCEPT
```

## 11. 快速决策流程

```
你需要跟朋友异地局域网联机
  │
  ├─ 游戏能直接输入 IP 地址？
  │   ├─ 是 → WireGuard（延迟最低）
  │   └─ 否 → 往下看
  │
  ├─ 不想碰命令行？
  │   └─ 是 → Tailscale（零配置 + 手动输 IP）
  │           或 ZeroTier（需广播则选这个）
  │
  ├─ 游戏必须有局域网扫描 / 广播？
  │   ├─ 是 → ZeroTier（开启桥接）或 n2n
  │   └─ 否 → WireGuard
  │
  └─ 特殊老旧游戏（什么都试过了都不行）？
      └─ OpenVPN tap 模式
```

## 12. 常见问题

### Q1: 云服务器配置要多高？

极低。虚拟局域网不耗资源：

- **CPU**：1 核足够
- **内存**：512 MB 即可
- **带宽**：取决于游戏。Minecraft 约 100 KB/s/人，FPS 游戏约 50-100 KB/s/人
- **流量**：用按量计费模式，玩游戏才跑流量

### Q2: WireGuard 和 Tailscale 有什么区别？

Tailscale 本质是 WireGuard 的上层封装，多了自动密钥交换、NAT 穿透、DERP 中继等。如果你愿意手动配 WireGuard，性能和灵活性更高；如果不想折腾，Tailscale 开箱即用。

### Q3: 游戏主机的人需要做什么额外操作吗？

不需要。主机正常创建房间，客机用主机的虚拟 IP 连接即可。但需注意：

- 游戏内服务器应绑定 `0.0.0.0`（而不是 `127.0.0.1`）——大多数游戏默认如此
- 主机的防火墙需允许虚拟网卡（`wg0` / `zt0` 等）上的游戏端口入站（见 10 节）

### Q4: 三个以上的人联机能行吗？

完全可以。方案不变，只需在 WireGuard 服务器配置中添加更多 `[Peer]` 段，或在 ZeroTier / Tailscale 后台授权更多设备即可。

### Q5: 用手机热点能联机吗？

能。WireGuard / Tailscale / ZeroTier 都是通过互联网建立隧道，手机热点本质上就是互联网连接。但注意：

- 移动网络通常是**对称 NAT**，打洞成功率较低
- 建议使用有服务器中转的方案（WireGuard 星型拓扑、Tailscale DERP 中继）

### Q6: 能用 frp 做端口映射代替虚拟局域网吗？

技术上可以，但不推荐。frp 将游戏端口从你的 PC 映射到云服务器的公网端口：

```
朋友的游戏包 → 云服务器:27015 → frp → 你的 PC:27015
```

**缺点**：
- 需要为每个游戏端口单独配置（麻烦）
- 不适用多端口通信的游戏（很多游戏不止一个端口）
- 没有真正的局域网语义（广播、设备发现都不行）

虚拟局域网是更优雅的解决方案。
